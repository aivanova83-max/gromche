# Страница текстов песен «Громче» (`/songs/<slug>`)

Эти страницы участники открывают с телефона на хоровой вечеринке и подпевают.
Каждая страница почти дословно повторяет `src/pages/SongsFilms26.tsx` — это
эталон. Задача скилла: собрать новую такую страницу по эталону, ничего не
изобретая в вёрстке, и довести до pull request.

**Что скилл делает только новую страницу.** Если Аня просит поменять тексты,
шапку, порядок песен или оформление на *уже существующей* странице — это обычная
ручная правка, скилл не нужен.

## Предусловие: страница мероприятия должна уже существовать

slug новой страницы = slug страницы мероприятия. Например `/events/kudaleto` →
`/songs/kudaleto`.

Прежде чем что-либо создавать, проверь, что мероприятие есть:

- в `src/App.tsx` есть маршрут `/events/<slug>`;
- есть файл `src/pages/Event<Slug>.tsx`.

**Если такой страницы мероприятия нет — остановись и спроси Аню**, к какому
мероприятию делаем тексты (или попроси сначала завести страницу мероприятия). Не
придумывай slug сам и ничего не создавай до ответа.

## Что взять у Ани (вход)

1. **Какое мероприятие** — из него берётся slug, ничего не выдумывай.
2. **Две строки шапки**, дословно:
   - заголовок (название мероприятия, напр. «Куда уходит лето»);
   - подпись под ним (напр. «Хоровое застолье 23 августа»).
   Аня диктует их сама — не тащи из данных мероприятия.
3. **Список песен по порядку исполнения**: название, при желании «к/ф «…»» или
   исполнитель, и текст. Если чего-то из этого нет — см. правило про заглушки.

Если шапки или списка песен в запросе нет — попроси их до начала работы.

## Шаги

Порядок именования по slug (пример: slug = `kudaleto`):

| Кусок | Путь / имя |
|---|---|
| Данные | `src/data/songsKudaleto.ts`, экспорт `songsKudaleto` |
| Страница | `src/pages/SongsKudaleto.tsx`, компонент `SongsKudaleto` |
| Маршрут | `<Route path="/songs/kudaleto" element={<SongsKudaleto />} />` |

Первая буква slug в имени файла данных — строчная (`songsKudaleto.ts`), в имени
компонента и файла страницы — заглавная (`SongsKudaleto`). Это совпадает с уже
существующими `songsFilms26.ts` / `SongsFilms26.tsx`.

### 1. Файл данных

Скопируй `reference/data-template.ts` в `src/data/songs<slug>.ts`, подставь имя
экспорта и заполни массив:

- `id` — строки `"1"`, `"2"`, … по порядку;
- `title` — название песни;
- `artist` — «к/ф «…»» или исполнитель, иначе пустая строка `""`;
- `lyrics` — **полный текст, который прислала Аня, дословно**, между обратными
  кавычками, с сохранением пустых строк между куплетами.

**Тексты и авторское право.** Вставляй ровно то, что прислала Аня — это её
контент на её же странице, закрытой от поисковиков (`noindex`). **Сам тексты
песен из интернета не ищи и не подставляй.** Для песни, к которой Аня текст не
прислала, ставь заглушку `[текст добавить]`. В конце работы отдельным списком
скажи Ане, у каких песен остались заглушки.

Файл данных кладётся в `src/data/` (правило 16 из CLAUDE.md) — не объявляй массив
песен внутри файла страницы.

### 2. Страница

Скопируй `reference/page-template.tsx` в `src/pages/Songs<Slug>.tsx` и замени
только четыре токена: `__SLUG_PASCAL__`, `__SLUG_CAMEL__`, `__HEADER_TITLE__`,
`__HEADER_SUBTITLE__`. Всё остальное — часть эталона `SongsFilms26.tsx`, не
трогай:

- макет под телефон (`max-w-[600px]`), шапка с логотипом-ссылкой на телеграм;
- кнопки `A−` / `A+` (шаг шрифта 12–32, старт 17);
- сайдбар со списком песен;
- блок «Следующая песня» и пустой каркас `NEXT_SONG_OVERRIDES` (заполнять только
  если Аня явно просит пропустить песню в цепочке «следующая»);
- `<meta name="robots" content="noindex, nofollow">` через `useEffect`;
- цель Яндекс.Метрики `song_change` (`window.ym(109163310, …)`);
- нижний блок-CTA «Эту песню вы пели с «Громче»…» и верхний баннер «Пой вместе
  с нами…» — текст оставляй как в эталоне, он общий для всех мероприятий.

В шаблоне есть `style={{ fontSize: … }}` — это законное исключение из запрета на
inline-стили (динамическое значение от кнопок `A−`/`A+`), так в эталоне. Больше
inline-стилей не добавляй, цвета — только через токены (`folk-*`, `ochre`,
`header-panel` и т.п.), без HEX.

### 3. Маршрут

В `src/App.tsx`: добавь `import Songs<Slug> from "./pages/Songs<Slug>";` рядом с
другими импортами страниц песен и `<Route path="/songs/<slug>" element={<Songs<Slug> />} />`
**выше** строки-катч-олла `<Route path="*" …>` (там есть комментарий-напоминание).

### 4. Ссылка со страницы мероприятия

На `src/pages/Event<Slug>.tsx` добавь заметную ссылку/кнопку «Тексты песен»,
ведущую на `/songs/<slug>`. Повтори оформление уже существующих
кнопок/ссылок на этой странице (те же токены и классы, без HEX и без inline-стилей).
Логичное место — рядом с блоком «что вас ждёт» / деталями мероприятия.

### 5. Визуальная проверка (обязательна, CLAUDE.md §10)

1. Подними dev-сервер (`npm run dev`, порт 8080).
2. Открой `http://localhost:8080/songs/<slug>` через браузерные инструменты.
3. Прокликай сценарий: открой сайдбар, выбери другую песню, нажми `A−` и `A+`,
   перейди по «Следующая песня». Проверь мобильную ширину (~375px).
4. Сними скриншоты до и после взаимодействия.
5. Проверь консоль на ошибки.

Если что-то сломано или съехало — почини и повтори. После двух проходов без
прогресса — остановись и расскажи, в чём затык.

### 6. Ветка, коммит, PR — и стоп

- Ветка `feat/songs-<slug>` (не пушить в `main` напрямую).
- Коммит на русском: `feat: страница текстов песен /songs/<slug>`
  и в конце тела —
  `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`
- Открой pull request, тело завершай строкой
  `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
- **На этом скилл заканчивается.** Отдай Ане ссылку на PR и список песен с
  заглушками. Слияние PR Аня делает сама — не мёржи.

## Правила проекта, которые нельзя нарушать

Из `CLAUDE.md`: импорты только через алиас `@/`; цвета только через токены, без
HEX в JSX/CSS; без `style={{}}` (кроме готового `fontSize` в шаблоне); статические
данные — в `src/data/`; не трогать `src/components/ui/`; не пушить в `main`, всё
через PR; коммиты на русском с префиксом (`feat:` / `fix:` / …).

## Примеры

**Пример 1 — вывод имён из slug.**
Аня: «Сделай страницу с текстами песен для вечеринки „Куда уходит лето“».
Мероприятие — `/events/kudaleto`, значит:
- данные → `src/data/songsKudaleto.ts` (экспорт `songsKudaleto`);
- страница → `src/pages/SongsKudaleto.tsx` (компонент `SongsKudaleto`);
- маршрут → `/songs/kudaleto`;
- ссылка «Тексты песен» на `src/pages/EventKudaleto.tsx`.

**Пример 2 — нет страницы мероприятия.**
Аня: «Нужна страница текстов к новогоднему концерту».
В `src/App.tsx` нет маршрута `/events/newyear`, файла `EventNewyear.tsx` тоже нет.
→ Остановись: «Страницы мероприятия `/events/newyear` пока нет. К какому
мероприятию делаем тексты, или сначала завести страницу мероприятия?» Ничего не
создавай до ответа.

**Пример 3 — заглушки для текстов.**
Аня прислала 8 названий, но тексты только к 5 песням.
→ У 5 песен `lyrics` — присланный текст дословно; у 3 — `[текст добавить]`.
В финале: «Заглушки остались у песен: „…“, „…“, „…“ — пришли тексты, и я вставлю».

## Когда НЕ применять

- Правки уже существующей страницы песен (тексты, шапка, порядок, вид) — вручную.
- Полноэкранный показ текстов на большом экране на самом мероприятии →
  `gromche-horaoke`.
- Пост / карусель / слайды для соцсетей → `gromche-carousel*`.
